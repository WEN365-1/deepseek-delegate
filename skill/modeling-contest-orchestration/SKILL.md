# 数学建模竞赛：人 + 多 AI 协作打法

本 skill 是一套经过完整比赛验证的流程（2026 MathorCup 大数据赛道 A，67 页论文、三问建模、多轮 AI 审查后提交）。核心分工：**人做授权与判断，Claude 做主控大脑，DeepSeek 做执行手，Kimi 做多模态眼睛。** 派活机制见 `deepseek-delegate` skill，本文只讲比赛怎么打。

## 一、角色与原则

| 角色 | 负责 | 不负责 |
|---|---|---|
| 人 | 选题方向、提交/删除/推送等授权、最终验收 | 不替 AI 写正文、不手工改数 |
| Claude（主控） | 拆题、定方案、写指令、审稿、核数、把关、写论文骨架与关键段落 | 不做大批量体力活 |
| DeepSeek（执行） | 跑脚本、训练、批量改文件、生成图表、盘点、git 操作 | 不做判断、不擅自扩范围 |
| Kimi（多模态） | 版面检查、表格续页、图片文字识别、扫描件核对 | 不碰数据与结论 |

三条铁律：
1. **回报不等于事实。** 执行模型说"完成"之后，主控必须用只读方式抽查关键数字和文件是否存在。
2. **每轮开工前打 git 快照。** 这是唯一可靠的退路；执行模型不做 commit/checkout/reset。
3. **对外与不可逆操作必须由人授权**：推送、删除、上传、提交、签名。

## 二、赛前准备（开赛 1 小时内完成）

1. 建工作区并 `git init`，写好 `.gitignore`：赛题原件、队友文件、`**/原始附件_只读/`、`.venv`、`__pycache__`、`*.zip`、大结果文件不入库。
2. 建交接目录 `Claude协作/`，放 `README.md` 写明：根目录绝对路径、Python 命令名（Windows 常是 `python` 不是 `python3`）、依赖版本、禁止事项。
3. 冻结环境：`requirements.txt` 记录 NumPy/pandas/scikit-learn 等精确版本；论文里也写明。
4. 建 `work_Q1/ work_Q2/ work_Q3/` 三问目录 + `work_integration/` 汇总目录，每问内部统一 `code/ results/ figures/ docs/`。
5. 建证据台账 `证据台账.csv`：每个关键数字一行（来源脚本、输出文件、数值、负责人），后续论文引用只从这里取。

## 三、拆题与并行（第 1–3 天）

- 主控先把赛题拆成「数据理解 → 三问各自的最小可行模型 → 汇总口径」。**先写一页解题骨架**，再动手。
- 三问互相独立就并行：每问一个执行模型，指令开头写清"本块只允许写 `work_QN/`"。
- 每问先跑**基线**（均值/零模型/简单回归），再上复杂模型；所有对比都要有基线。
- 结果落盘规范：脚本输出必须带 `seed`、`metrics.json`、`predictions.csv`，图表由脚本生成而不是手改。
- 检查点写法：每步给验收标准（文件存在、行数、指标区间），失败即停并贴原始输出。

## 四、论文成稿（第 3–5 天）

1. **先定骨架**：章节、每节要放的表和图、页数预算（正文通常 15–20 页）。骨架定完再填内容。
2. **摘要最后写**，但摘要里的每个数字必须能在证据台账里找到。
3. 图表全部由脚本生成；表格统一三线表；跨页表必须补"续表"题注，避免整页留白。
4. 评分卡/矩阵类表格按模板**逐格填**，不要留"待补"。
5. 局限要**如实写**：没通过门槛的种子、偏宽的判定规则、未做真实复现的部分，主动披露比被评委发现好。
6. 榜单类结果要**正反都报**：只报正面会显得不可信。

## 五、多轮交叉审查（第 5–6 天）

推荐四层，逐层收敛：

1. **自审**：主控按 `bzd-*` 系列检查 skill（摘要、格式、模型、参考文献、AI 合规）逐项过。
2. **队友审查**：把论文和材料打包给队友，收集问题清单。
3. **第三方 AI 汇总审查**：多方结论合并成一份 `合并修改计划.md`，按 P0/P1/P2 排序。
4. **逐轮修改**：每轮一个 git 快照 + 一份指令 + 一份回报；改完重新跑自动校验脚本。

合并原则：**以主稿为骨架**，吸收他人方法上的优点（如阈值扫描、零模型、最优传输迁移），不整段替换。

## 六、踩过的坑（务必逐条检查）

- **文件元数据泄露姓名**：PDF/Word 的作者、最后修改者字段常含真名。提交前用脚本扫描所有条目的元数据与正文，不只是文件名。
- **参考文献编号顺序**：增删文献后正文引用编号会错位，必须用脚本核对"正文首次出现顺序 = 文末编号顺序"。
- **AI 使用日期不一致**：声明、详情 PDF、日志三处日期要统一，并在提交前再核一遍。
- **附件目录与工作区不一致**：打包后要解压到干净目录，按论文里的路径实际跑一遍。
- **续页题注缺失 / 空白页**：渲染后逐页看，或用脚本检测空白页与孤立表头。
- **只交论文和代码**：赛题常要求单独上传计算结果（评分表等），核对题面。
- **承诺书不能自动生成签名**：必须队员真实签名后另存 PDF。
- **上传后不确认**：必须看到页面显示"电子档已提交"并截图留存。

## 七、AI 合规披露

- 统一口径：工具名 + 版本 + 使用日期区间，三处（论文声明、AI 详情 PDF、附录）一致。
- 详情要写到"哪个环节用了哪个模型、做了什么、人做了什么判断"，不能只写"使用了 AI"。
- 匿名要求：AI 详情 PDF 与论文一样不能出现姓名、学校等身份信息。
- 用 `bzd-ai-usage-disclosure` skill 做一致性检查。

## 八、提交包构建与提交前核对

1. 用脚本构建提交包（不要手工压缩），输出 `build_report.json`（条目数、哈希、排除清单）。
2. 跑自动复核：文件存在性、页数、空白页、姓名扫描、Python 语法、路径一致性。
3. 按 `references/提交前核对清单.md` 人工过一遍。
4. 上传三件套 → 点击"提交电子档" → 确认状态 → 保存截图与哈希。
5. 提交后**不要再改文件**；如需改动，重新走一遍构建与核对。

## 九、赛后整理与沉淀

- 顶层只留两个目录：`00_最终提交/`（三件套 + 提交说明含哈希）与 `99_归档_过程材料/`（其余全部）。
- 归档里保留原工作目录结构，脚本重跑时把归档目录当根目录。
- 把本轮新增的坑补进本 skill 的第六节，让下一次少踩一次。
