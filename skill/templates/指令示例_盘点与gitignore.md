> 示例：一个真实跑通过的首轮指令（项目还没有 git 时，先盘点再起草 .gitignore）。

# 指令 YYYY.MM.DD.HH.MM：盘点项目文件 + 起草 .gitignore

> **本轮执行方：DeepSeek**（全程只由该模型执行）。先读 `<项目根>/_claude/README.md`。
> **授权情况**：只读盘点 + 新建 3 个文件（见下）。禁止删除、禁止修改任何已有文件、禁止任何 git 写操作（项目还不是 git 仓库，主控审核后再初始化）。

## 背景
- 项目根：`<项目根>`（下称 ROOT）。目录里混着代码、文档、点云数据、缓存、`.venv`，总量可能很大。
- 目标：主控要给 ROOT 建一个本地 git 仓库，只跟踪代码、配置、文档和小结果文件。本轮先把"哪些东西大、该排除"摸清楚，并起草 `.gitignore`。

## 步骤

### 第 1 步：写盘点脚本
新建 `ROOT/_claude/tools/inventory_YYYY.MM.DD.HH.MM.py`（`tools` 目录不存在就新建），要求：
- 用 `os.walk` 遍历 ROOT，**跳过** `.venv`、`.git`、`__pycache__` 目录（不进入，但要把这些目录的总大小单独统计出来）。只读文件元数据（大小），不打开文件内容。
- 输出写到 `ROOT/_claude/inventory_YYYY.MM.DD.HH.MM.txt`（UTF-8），包含四节：
  1. 每个顶层条目（ROOT 下一层的目录和文件）的总大小（MB）和文件数，按大小降序；
  2. 按扩展名汇总：文件数、总大小（MB），按总大小降序，列前 40 个；
  3. 所有 > 5 MB 的单个文件：相对路径、大小（MB），按大小降序，最多列 300 个，超出就写"其余 N 个省略"；
  4. 小于等于 5 MB 的文件里，扩展名为 `.py .md .txt .json .yaml .yml .ini .cfg .toml .csv .sh .bat .ipynb` 的文件数和总大小。
- 路径里有中文和空格，注意编码；遇到无权限或读不了大小的文件就跳过，并在输出最后列出这些路径。

### 第 2 步：运行脚本
```
cd "<项目根>" && python "_claude/tools/inventory_YYYY.MM.DD.HH.MM.py"
```
- 验收：`_claude/inventory_YYYY.MM.DD.HH.MM.txt` 存在，四节齐全。
- 失败时：停下，把报错原样贴进回报，不要继续第 3 步。

### 第 3 步：起草 `.gitignore`
根据盘点结果，新建 `ROOT/.gitignore`（如果已存在，**不要覆盖**，改为新建 `ROOT/_claude/gitignore草稿_YYYY.MM.DD.HH.MM.txt` 并在回报里说明）。原则：
- 必须排除：`.venv/`、`__pycache__/`、`*.pyc`、所有缓存目录（以盘点实际看到的为准）、点云与数组与权重（`*.ply *.las *.laz *.npy *.npz *.pt *.pth *.ckpt *.h5`）、压缩包（`*.zip *.rar *.7z *.tar *.gz`）、以及盘点里出现的其他大体积数据类型。
- 第 3 节列出的每个 > 5 MB 文件，如果没被上面的规则覆盖，就按它所在目录或扩展名补一条规则；实在不好归类的，按相对路径单独写一行。
- 不要排除 `.py .md .txt .json .yaml .ini .csv` 这类小文件，除非它们 > 5 MB。
- 每组规则前写一行 `#` 注释说明为什么排除。
- 验收：第 3 节的每个文件都能被某条规则覆盖。在回报里逐条对照说明（文件 → 覆盖它的规则）；文件太多时按目录归组说明。

## 回报
写进 `ROOT/_claude/DeepSeek回报_YYYY.MM.DD.HH.MM.md`，包括：
- 每步 PASS / FAIL
- 第 2 步运行命令的原始输出（最后 20 行）
- 盘点结果摘要：总大小、最大的 10 个顶层条目、> 5 MB 文件的个数
- `.gitignore` 全文
- 第 3 步的覆盖对照
- 异常与不确定之处（例如：某些目录不确定是数据还是代码）

## 禁止事项
- 不准删除、移动、重命名、修改任何已有文件
- 不准运行任何 git 写操作（init / add / commit 等）
- 不准安装任何 Python 包；只用标准库
- 不准读取大文件的内容
