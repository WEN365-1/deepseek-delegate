# AI 协作工作流（Kimi Work 适配版）

## 角色

| 角色 | 负责 | 不负责 |
|---|---|---|
| Kimi 主控 | 理解目标、拆解任务、写指令与验收标准、独立抽查、风险与质量把关 | 不盲目相信执行方自述，不自动做 Git 写操作 |
| DeepSeek 执行方 | 按指令使用本轮开放的文件或 Python 工具，提供证据和如实回报 | 不继承 Kimi 工具，不擅自扩大范围，不处理未转写成文字的视觉输入 |
| 用户 | 做授权决定、私密配置 API Key | 不需要在两个模型之间传话 |

## 默认分工

把边界清楚、输出可验收的工作优先交给 DeepSeek：盘点、重复计算、独立复算、批量文本处理、代码或文档初稿、明确标准下的审查。

以下工作由 Kimi 保留：任务目标与验收标准、图片或图纸理解、需要 Kimi 专属工具的步骤、风险判断、关键结果抽查、最终整合。一步即可完成的小任务不必委派。

## 指令要求

1. 每轮只交给一个执行模型；一轮内尽量合并有顺序关系的步骤。
2. 写清项目根、相关文件、已知事实、允许写路径和禁止事项。
3. 每一步都有 PASS 标准；失败时停止后续依赖步骤并保留原始错误。
4. 对计算任务，写明输入、单位、公式或判定标准、预期输出结构；不要只问“对不对”。
5. 对写作任务，提供已核实材料与必须保留的引用，禁止编造未提供的事实。
6. 要求回报包含：每步 PASS/FAIL、关键原始输出、改动文件、异常与不确定之处。

## 验收

- 回报只是执行方自述。Kimi 至少独立核实最关键的一项客观证据。
- 文件任务检查文件存在性、路径范围和内容；计算任务抽查输入、单位和关键数字；代码任务运行或检查针对性测试。
- 并行任务额外检查每个执行方是否越出分配路径。
- 不通过时写返工指令；只有一步即可修正且委派成本更高时，Kimi 才直接修正并说明原因。

## 交接文件

- `_kimi/deepseek/README.md`：项目环境、路径与长期纪律。
- `Kimi指令_YYYY.MM.DD.HH.MM.md`：本轮指令。
- `DeepSeek回报_YYYY.MM.DD.HH.MM.md`：最终文字回报。
- `DeepSeek运行_YYYY.MM.DD.HH.MM.json`：状态、工具事件和 API token 用量，不含 API Key。
- `history/`：已验收轮次的归档。
